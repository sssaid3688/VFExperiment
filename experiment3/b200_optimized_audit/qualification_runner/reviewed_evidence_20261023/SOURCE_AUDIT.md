The DenseMM [Blackwell WS comment and loop](https://github.com/triton-lang/triton/blob/7c56a5e40f7fd928dfd5c72902d5def0097db73a/python/tutorials/09-persistent-matmul.py#L398) explicitly tie warp specialization to Blackwell. Attention has an [explicit major10 predicate](https://github.com/triton-lang/triton/blob/7c56a5e40f7fd928dfd5c72902d5def0097db73a/python/tutorials/06-fused-attention.py#L39), [Blackwell accumulator branch](https://github.com/triton-lang/triton/blob/7c56a5e40f7fd928dfd5c72902d5def0097db73a/python/tutorials/06-fused-attention.py#L87), and [register settings168/80](https://github.com/triton-lang/triton/blob/7c56a5e40f7fd928dfd5c72902d5def0097db73a/python/tutorials/06-fused-attention.py#L542). The selected128x64,4warp,2stage configuration is the tutorial's reproducibility test configuration. The exact kernel hardcodes the probability/output type to FP16 or E5M2; it cannot provide a matched FP32 or E4M3FN measurement. QK/PV accumulators and LSE are FP32, with unnormalized probabilities rounded to the selected storage precision before PV. E5M2 has no scales, so this is not MXFP8.

Static coordinate analysis identifies a v3.6.0 FP8 V descriptor issue for multihead batches: its descriptor is `[D,B*H*S]` with strides`[S,1]`, but loads advance the second coordinate by `head*S*D`. On96/100 prespecified shapes this exceeds the declared second dimension for at least one head. This is a source-level bounds finding, not a GPU reproduction. The [pinned current upstream kernel](https://github.com/triton-lang/triton/blob/93035c4472eb820f78074de0e28341fa321a759d/python/tutorials/06-fused-attention.py#L198) uses `[B*H*D,S]` and `[head*D,start_n]`, which the adapter uses unchanged. Its API use is compatible with installed descriptor primitives by static inspection; compilation is pending. FP16 uses the v3.6.0 leaf without this transposed-V branch.

Official08 [grouped-TMA implementation](https://github.com/triton-lang/triton/blob/7c56a5e40f7fd928dfd5c72902d5def0097db73a/python/tutorials/08-grouped-gemm.py#L231) uses a device scheduler over arrays of independent GEMM pointers, sizes and leading strides. BMM batches and GroupGEMM row groups map to these independent products without changing the mathematical operation. B is physically packed to `[G,N,K]` before timing. A/C pointers are disjoint contiguous views; no per-group allocation or arithmetic occurs in the timed callable. Metadata is int64 pointers plus int32 sizes/strides, with metadata reads counted. The kernel hardcodes FP16/E4M3FN pointers, so interpreting FP32/E5M2 through it would be invalid.

All four operators retain exactly the previous100 unique shapes at each index, including SDPA S512/1024 and D64/128. DenseMM B and FP8 attention V packing are outside timing and recorded explicitly. Native CPU FP64 references use actually rounded input values. Timed functions contain only Triton launches. Device-descriptor paths receive a64MiB preallocated allocator workspace and fail if a larger/aligned allocation is requested; this requires a serial runner. Descriptor scratch bytes are disclosed separately from useful algorithmic traffic. DenseMM/GroupMM packing time is not part of the kernel measurement.
